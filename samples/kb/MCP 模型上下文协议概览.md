# MCP 模型上下文协议概览

MCP（Model Context Protocol，模型上下文协议）是一个开放标准，用来规范大模型应用与外部数据源、工具之间的连接方式。本篇说明它要解决的问题、Host-Client-Server 三种参与者的职责划分，以及连接建立时的能力协商机制。

## 解决什么问题

没有统一协议时，接入是 M×N 的灾难：M 个模型应用要各自为 N 个数据源写适配器，重复劳动且难以维护。MCP 把 M×N 收敛成 M+N——应用方与工具方各自实现一次协议，就能两两互通。上下文（文件、数据库记录）与动作（查询、写入、调用）由此有了统一的接入标准，生态里每个新工具对所有应用即插即用。

## Host、Client 与 Server 三种参与者

MCP 的运行时由三种角色构成。Host 是模型应用本体，比如 IDE 助手或聊天客户端，负责发起请求、汇总结果并把权限留在用户一侧；Client 位于 Host 内部，与某个 Server 保持一对一连接，负责协议握手与消息转发；Server 是能力提供方，把文件系统、数据库或第三方 API 封装成标准化的工具与资源对外暴露。一次问答里，Host 决定用什么，Client 负责传话，Server 负责干活。

## 能力协商

客户端与服务器在初始化握手时交换各自支持的能力清单：服务器声明自己提供哪些工具、资源与提示模板，客户端声明支持的协议版本与交互特性。协商完成后，双方只在共同支持的能力子集内工作，不会调用对方不具备的功能。这种机制让协议可以平滑演进：新增能力不影响旧版本之间的互通。

## 典型工作流程

一次完整的调用大致是：Host 启动时与各 Server 建立连接并完成能力协商；用户提问后，模型按需选择某个工具，Host 经由对应的 Client 把调用请求发给 Server；Server 执行后返回结果，结果进入模型上下文参与后续生成。敏感操作由 Host 逐项请示用户，批准后才真正执行。
