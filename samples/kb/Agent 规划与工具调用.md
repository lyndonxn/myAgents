# Agent 规划与工具调用

Agent 与普通问答机器人的分野在于自主性：它能先把复杂问题拆解成可执行的步骤，再调用工具逐个落实，并在中途根据结果调整方向。本篇依次介绍任务拆解、ReAct 循环、反思与重规划，以及工具注册与失败降级。

## 任务拆解

面对"对比 A、B 两个方案并给出选型建议"这类多跳问题，单次检索往往不够。规划层先把目标拆成有序的子任务：先分别检索两个方案的资料，再做对比，最后综合成结论。每个子任务对应一次工具调用，拆解结果以带编号的计划呈现，既方便逐步执行，也方便用户审查推理路径。

## ReAct 循环

ReAct 是让模型交替进行推理与行动的经典范式：思考（Thought）决定下一步该做什么，行动（Action）调用某个工具，观察（Observation）拿回工具结果作为下一轮思考的依据。三者循环往复，直到模型认为证据足够，才把观察到的内容综合成最终答案。推理与行动互相印证，比一次性规划更抗噪。

## 反思与重规划

一轮执行结束后，Agent 可以回看步骤轨迹做自我检查：哪一步失败了？哪些信息还没拿到？需要补哪个工具调用？反思产出新的补充步骤，续接在原计划之后执行，并设置总步数上限防止无限循环。这种"先干、再看、再补"的迭代，比一次性把计划列全更贴合真实任务的不确定性。

## 工具注册与降级

工具以统一接口注册：名称、描述、参数结构，模型据此选择调用哪个工具。健壮性来自两条兜底规则：一是失败重试，工具抛错后按配置重试若干次；二是降级路径，知识库检索重试耗尽后自动切换到备用方案（如网页搜索），规划本身失败时则退化为单步直接检索。工具永远可能失败，完整的降级链路是 Agent 可用性的底线。
