# RAG 检索增强生成入门

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把外部知识检索与大模型生成结合起来的问答架构：系统先根据用户问题从知识库里找出相关片段，再把片段当作证据交给模型组织答案。本篇介绍它的基本定义、出现的动机，以及端到端的整体流程。

## 什么是 RAG

RAG 的核心思路是"先查资料、再作答"。模型本身只负责理解问题与组织语言，事实性内容来自检索到的知识库片段。这样，答案的依据可以落到具体文档上，既能标出引用出处，也能在片段缺失时明确告知"未找到相关信息"，从机制上压低编造答案的风险。

## 为什么需要 RAG

大模型的参数在训练完成后就固定了，面对新资料、企业内部文档或私人笔记往往一无所知；把整本文档直接塞进上下文窗口又会撞上三重限制：窗口长度装不下、按 Token 计费的成本高、无关内容还会稀释模型注意力。RAG 用"按需检索"化解这些矛盾：每次只取最相关的几段，答案更准、开销更小；知识库更新后无需重新训练模型，时效性也更有保障。

## RAG 的整体流程

一套完整的 RAG 流程分两条线。离线索引阶段：加载文档、清洗噪音，按标题与长度切成片段（Chunk），再用 Embedding 模型把片段编码成向量并建立索引。在线问答阶段：用户提问后，系统先用向量与关键词两路召回候选片段，经重排筛出最相关的若干条，最后把片段连同问题一起交给大模型，生成带引用的答案。两个阶段合起来，就是"分片 → 索引 → 召回 → 重排 → 生成"五个环节。
